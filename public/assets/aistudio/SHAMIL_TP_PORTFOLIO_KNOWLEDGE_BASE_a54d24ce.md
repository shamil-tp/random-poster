- **Development Type:** 100% Solo Project (67 commits, 2 tagged releases: v1 -> v2 architectural redesign)
- **Links:**
  - **Live Application:** https://lume-one.vercel.app/
  - **GitHub Repository:** https://github.com/shamil-tp/LUME
- **Technology Stack:**
  - **Backend & Workers:** Node.js, Express.js, BullMQ, Redis (`ioredis`), `tus-node-server`, FFmpeg (`fluent-ffmpeg`), AWS S3 SDK (`@aws-sdk/client-s3`)
  - **Cloud Object Storage:** Cloudflare R2
  - **Database & Auth:** MongoDB, Mongoose ODM, Google OAuth 2.0, JWT
  - **Frontend:** React.js, Vite, Uppy (`@uppy/core`, `@uppy/tus`), `hls.js`
- **Architecture & Technical Implementation Details:**
  1. **5-Stage Decoupled Event-Driven Pipeline:** Redesigned from a synchronous v1 upload server into an asynchronous v2 pipeline so CPU-intensive FFmpeg encoding never blocks the Express HTTP event loop:
     - **Stage 1 (Resumable Ingestion):** Client uploads large video files in chunks via Uppy to `tus-node-server`. Network interruptions resume from the last acknowledged byte offset.
     - **Stage 2 (Non-Blocking Queueing):** On upload completion, the API enqueues a transcoding job in Redis via BullMQ and immediately returns a processing status to the user.
     - **Stage 3 (Isolated FFmpeg Worker):** An independent Node.js worker (`worker.js`) consumes the BullMQ queue and invokes FFmpeg (`fluent-ffmpeg`) to slice raw video into HLS `.m3u8` playlists and `.ts` media segments.
     - **Stage 4 (Zero-Egress Cloud Sync):** The worker uploads generated `.m3u8` and `.ts` files to Cloudflare R2 using the AWS S3 SDK (`s3Uploader.js`), updates the MongoDB video document, and deletes local temporary files.
     - **Stage 5 (Adaptive Playback):** Custom React video player (`LumePlayer.jsx`) built on `hls.js` streams the HLS manifest from Cloudflare R2 with adaptive bitrate switching.
  2. **Documented Bug Investigation:** Diagnosed and documented a Tus protocol upload offset/header handling bug in `TUS_UPLOAD_FIX_REPORT.md`.
